# ADR-017：受控 Agentic RAG Auto 与原链路兼容

- 日期：2026-09-24
- 状态：Accepted（方向已确认，尚未实现/验收）
- 关联：AGT-001～032；补充 ADR-014、ADR-015，不废弃原确定性链路。

## 背景

用户要求直接交付 auto，由单开关控制，不先建设两个手动产品模式。内网检索是 Dense Embedding + Milvus 内置 BM25，不依赖 Embedding sparse 接口。当前本地 Milvus Adapter 与内网 BM25 实现需先对齐。

## 决策

1. 关闭开关保留原链路；开启自动使用快路径或受控增强路径，API 不要求模式参数。
2. 在现有 rag-query-service 增加决策/工具模块，不新增部署服务，不依赖 LLM Wiki。
3. 模型提出经严格 Schema 校验的动作；代码强制权限、版本、预算与终止条件。
4. 原检索能力与答案校验复用；只在连接点增量改动，不复制整套答案图。
5. Run 冻结策略；增强路径共享全局预算，恢复不重置用量；保留引用与权限门禁。
6. 先完成 Agentic Auto，再按业务价值试点 Wiki；原 Wiki 计划作为后续候选保留。

## 后果与替代方案

拒绝完全自由 Agent：难以控制时间、权限和证据质量。
拒绝零旧代码改动的承诺：现有图依赖具体检索服务，需要窄接口与受控证据入口。
接受少量契约/执行入口/快照改动，必须用关闭开关回归和兼容性测试控制风险。
BM25 若存在部署侧差异先对齐，不自动改变已有 Collection 或重新入库。
