# ADR-002：单企业 userId + roles 身份模型

- 状态：Accepted
- 日期：2026-08-15
- 关联需求：AUTH-001～AUTH-005

## 背景

目标环境只有一个企业租户，上游登录系统最终能提供 `userId` 和 `roles`，但当前还不确定通过可信 Header、JWT 还是开发 Mock 传入。

## 决策

核心身份固定为服务端构造的 `Principal { userId, roles }`。传输方式由 `AUTH_MODE=mock|trusted-header|jwt` 适配，业务用例不读取原始 Header。系统不是多租户，但知识空间授权仍默认拒绝；客户端角色只能缩小范围，不能扩大上游已确认权限。

## 备选方案

- 业务代码直接读取 Header：实现快，但信任边界散落且难以审计。
- 立即绑定某个 IdP SDK：安全能力强，但当前接口未定，会把不确定性扩散到业务层。

## 结果

M01 可以在不改业务用例的前提下替换身份入口。可信 Header 模式必须由网关清除外部同名 Header，并限制来源网络。
