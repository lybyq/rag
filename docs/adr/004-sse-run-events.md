# ADR-004：SSE 只传递已持久化 Run 事件

- 状态：Accepted
- 日期：2026-08-15
- 关联需求：RUN-001～RUN-015

## 背景

问答需要流式进度、取消和断线续传。若服务直接把内存 Token 推给浏览器，断线后无法补发，服务崩溃时也无法判断答案是否完成。

## 决策

M06 使用带单调序号的 Run Event。关键状态和对外事件先持久化，再通过 SSE 发布；客户端携带 `Last-Event-ID` 续传。SSE 是投影视图，不是事实源。最终答案只有通过证据校验后才成为可见事件。

## 备选方案

- WebSocket：双向能力更强，但本场景主要是服务端推送，网关和续传实现更复杂。
- 只流模型 Token：延迟最低，但无法恢复且可能泄露未校验内容。

## 结果

可审计、可续传、可回放，代价是事件存储和批量刷新的额外开销。M00 只冻结决策，M06 实现。
