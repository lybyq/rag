# ADR-016：Parser 内容正确性、结构恢复、OCR 合并与资源预算

## 状态

Accepted，2026-09-05。细化并部分取代 ADR-011 中 PDF 结构抽取、OCR 替换条件、Office 图片定位和格式资源限制的结论；ADR-011 的 Node/TypeScript 路线、独立 Parser 服务、内置内容安全边界及 Port/Adapter 分层继续有效。

## 背景

现有 Node Parser 已能在外网和内网用同一套 HTTP 契约解析九类文件，但合成样本和代码追踪发现四类内容正确性风险：OCR 请求成功不等于每个目标都成功，Office 归档中的媒体文件顺序不等于文档阅读位置，HTML/Markdown/Office 的表格限制有些发生在完整物化之后，PDF 文字只输出为段落导致下游没有可靠标题路径。

内网 Provider 地址和现有协议已经联调通过。本轮必须收敛修改，不能为了修复内部算法而改变部署拓扑、环境变量含义或把供应商字段泄漏到领域层。

## 决策

### 1. OCR 部分失败与原生文本保留

1. `OcrTarget.targetId` 是一次调用中的幂等关联键。Adapter 必须拒绝重复和额外结果，并把缺失、空结果、定位不一致、低置信度与整个调用失败分开处理。
2. PAGE OCR 只有在对应目标实际返回、定位一致、至少含一个有效非空 Block 且达到质量阈值时，才替换同页不可靠的原生 Block。仅仅“请求了该页”绝不是删除原生内容的依据。
3. PAGE 结果不可用时保留原生 Block 并记录结构化 Issue。若原生文字层本身被判定不可靠，则任务进入有限重试或质量审核，不把该页当作可靠内容发布。
4. REGION、EMBEDDED_IMAGE 和 WHOLE_IMAGE 只在关联位置补充 OCR Block；它们不能删除整页原生文本。
5. 取消、Deadline、429/5xx 和响应契约错误继续沿现有 Port 错误分类传播，不在 Controller 或 Adapter 中吞掉。

### 2. 统一解析资源预算

1. `DocumentParserLimits` 扩展为统一预算输入，并由小型预算计数器在消费过程中累计实际单元格、展开单元格、最大跨度、行列、图片像素和输出规模。
2. 每次循环、数组扩容、合并单元格展开和字符串累计前检查预算；乘法先用安全整数检查，禁止通过 `rowspan * colspan` 制造隐式大分配。
3. HTML、Markdown、DOCX 共用结构抽取必须接收预算和 `AbortSignal`。CSV 按记录消费时累计，不先构造无限大小的二维数据集。
4. 第三方库无法在物化前限制的边界必须在格式文档和 Issue 中明确；外层独立 Parser 服务的 Deadline、容器 CPU/内存和进程终止仍是最后一道隔离门禁。
5. 超限返回稳定 `*_LIMIT_EXCEEDED` 错误，不截断后假装成功。

### 3. Office 图片与阅读位置关联

1. DOCX、XLSX、PPTX 必须通过各自 OOXML relationship 和 drawing/anchor 节点关联媒体资产，禁止按 ZIP 文件名、图片数量或字典序猜测。
2. “媒体资产”和“出现位置”是两个事实：同一媒体可被多次引用，每个出现位置都有稳定目标 ID、源部件、relationship、Sheet/Slide/段落锚点和必要坐标。
3. OCR Block 插入对应出现位置附近，不能统一追加到文档末尾。无法定位时保留资产并形成显式 Issue，不能伪造页码或零像素坐标。

### 4. PDF 结构化抽取与标题推断

1. 保持 Node/TypeScript 和独立 Parser 服务，优先使用当前锁文件中已有的 `pdfjs-dist` 能力获取 TextItem 字号、字体、变换、坐标和页面信息；新增依赖前必须通过许可证、离线构建和安全审计。
2. PDF metadata Title 只作为文档元数据，不直接生成正文标题。正文标题输出 `TITLE + headingLevel`，推断同时参考相对正文字号、字体、行位置、间距、长度、章节编号及可用目录/结构标签。
3. 每个推断标题记录算法 revision、依据和置信度；大字、加粗或短句单一特征不能直接判为标题。
4. 先恢复 TextItem 到行和段落，再处理分栏阅读顺序、跨页连续、重复页眉页脚和页码装饰；原始抽取文本始终可追溯。
5. 表格按版面位置进入阅读顺序，并避免与同一区域原生文本重复。旋转、裁剪和近似坐标必须显式标注，不能冒充像素级精确定位。

### 5. TXT、CSV 与图片支持边界

1. 文本编码不做概率猜测：只接受严格 UTF-8 和带 BOM 的 UTF-16LE/BE。检索文本统一换行为 LF，`originalText` 保留源换行；纯文本没有结构证据时不推断标题。
2. CSV 分隔符和表头是推断而非真相，必须记录算法 revision、置信度/依据和歧义 warning。列数不齐时保存源列宽并补成矩形，真实与展开预算分开计算。
3. 独立图片必须检查完整容器页/帧链和 Orientation。像素预算按全部页/帧累计，动画合成格式按完整画布估算。
4. 当前没有逐页/逐帧 derived 资产和 OCR Target 契约，因此多页 TIFF、动画 GIF/APNG/WebP 明确拒绝；禁止只处理首帧/首页后返回成功。
5. Orientation 只作为可审计事实保存；未实际重编码像素时返回告警，不声称已旋转。

## 兼容与版本决策

1. Parser/OCR HTTP `protocolVersion` 暂时保持 `2`。本轮优先使用现有字段完成严格校验和内部状态推导，不要求已经联调通过的内网 Provider 改请求路径或必填字段。
2. `PARSER_PROFILE_ID`、`OCR_PROFILE_ID` 及现有环境变量语义不变。Profile 表示部署选择，revision 表示实现语义，两者不能混用。
3. 阶段 1～8 开发期间默认 revision 保持 `1.0.0`，避免半成品被误带入内网；阶段 9 验收已把 Parser 算法 revision 统一升级为 `1.1.0`。OCR Provider 自身 revision 不因本地 Adapter 校验增强而伪造升级。
4. `document-blocks/v1` JSON 结构不升级，因为字段布局未发生破坏性变化。新 Parser revision 已写入快照内容、对象 Key 和 Hash；升级旧文档时必须新建 content revision 重处理，旧快照不得跨 Parser revision 复用。
5. derived 对象路径采用 `content-r{N}/parser-{profile}/revision-{revision}/blocks.json`。即使文档版本和 Parser Profile 相同，`1.0.0` 与 `1.1.0` 也写入不同对象，禁止因对象路径相同而错误命中旧 `HEAD`。
6. 新解析事实只有通过质量审核、索引构建和索引对账后才能原子切换 PostgreSQL ACTIVE Head。构建失败不改变当前 Head；回滚只把 Head 指回已发布历史版本，不删除或覆盖新旧 Block、Chunk、向量及审计事实。
7. 如果后续真实 PaddleOCR 必须表达“单目标失败原因”，先增加可选兼容字段并补契约测试；只有出现不兼容必填字段或语义重定义时才升级 OCR protocol。

## 取舍

- 保持协议 v2，减少已经联调通过的内网部署变更；代价是单目标失败先由“返回/未返回/空结果/置信度/调用异常”推导，Provider 私有错误仍只在 Adapter 内映射。
- 使用关系图恢复 Office 位置比归档排序复杂，但能消除图片错位这一类静默事实错误。
- 预算在分配前检查会增加少量计数开销，换取稳定内存上界和可预测失败。
- PDF 标题是可审计推断而不是绝对事实；低置信结果进入质量流程，不用“看起来像标题”污染 Chunk 路径。
- 严格编码和保守 CSV 表头会拒绝/降级少量模糊输入，换取不把乱码或第一条业务数据静默当成表头。
- 暂不支持动画/多页图片减少了格式覆盖，但避免当前 OCR 契约无法定位页帧时产生“成功但少内容”的数据污染。

## 验证

- 永久回归：OCR 空/缺失/重复/额外/错位/低置信/部分成功、正常短标题页和扫描页。
- 小预算合成样本：大跨度、稀疏表、超大行列、嵌套表格和取消。
- Office Golden：多图、重复媒体引用、非连续文件名、重排 PPT、真实 DOCX drawing relationship。
- PDF Golden：中英文标题、加粗反例、双栏、旋转、重复页眉页脚、表格去重、扫描和混合页。
- Chunking 联动：标题路径、章节边界、引用位置、正文不丢失且不重复。
- TXT/CSV/图片：UTF-16 边界、混合换行、CSV 方言/跨行/空记录/不齐列、TIFF 多页、GIF 动画、EXIF 方向、损坏头和累计像素。
