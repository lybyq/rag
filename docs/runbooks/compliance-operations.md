# 数据保留、审计与安全响应流程

## 角色与双人复核

- 请求人：提出范围、法律/业务依据和截止时间。
- SYSTEM_ADMIN：执行配置或技术动作。
- AUDITOR：复核范围、导出结果和完成证据。
- 安全事件不得由同一人提出、批准并关闭；开发 Mock 身份不能用于生产证据。

所有保留删除、审计导出、安全响应和密钥轮换先写入 `compliance_operation_jobs`，使用业务生成的唯一 `idempotency_key`。任务只保存非敏感摘要，不保存完整问题、密钥、预签名 URL 或受保护正文。

## 数据保留与删除

1. 依据企业批准的保留矩阵生成范围：会话/消息、上传隔离文件、派生文件、旧 Manifest、审计日志分别配置。
2. 先 dry-run 统计数量、最早/最晚时间、空间和不可删除法律保全项。
3. 审核通过后由幂等任务分批处理；PG 使用小批次锁，MinIO 只删除已核对对象键，Milvus 删除可推导旧 Manifest。
4. 会话正文按 `retention_expires_at` 脱敏/删除，摘要按独立期限清理；审计只记录计数与哈希。
5. 完成后对账 PG、MinIO、Milvus，`result_summary` 保存数量和失败数；部分失败保持 FAILED，可用同一幂等键续跑。

## 审计导出

1. AUDITOR 在审计页按用户、角色、动作、资源、结果和时间收窄范围。
2. `/api/v1/operations/audit/export` 最多导出 10,000 条脱敏字段，并记录一次 `AUDIT_EXPORT` 审计。
3. CSV 对公式控制字符转义；导出文件进入受控目录，设置过期时间和下载审计。
4. 不导出问题全文、证据正文、密钥、预签名 URL 或内部异常堆栈。

## 安全事件响应

1. 发现疑似泄漏后立即保全审计、Trace、Run 快照和受影响版本，关闭相关入口或 Feature Flag。
2. 识别用户、角色、空间、文档版本、引用和时间窗；不得扩大访问权限帮助排查。
3. 轮换疑似泄漏凭据，撤销会话/令牌，修复后运行权限与安全 Golden Set。
4. 由安全负责人确认影响和通知范围；恢复服务后持续观察告警。
5. `SECURITY_RESPONSE` 任务只保存事件编号、阶段、影响计数和证据位置哈希。

## 密钥轮换

1. 在密钥管理系统创建新版本，不把值写入 Git、日志、工单或浏览器。
2. 先把新密钥部署到少量实例并检查 Provider health/compatibility；双密钥窗口内验证调用。
3. 灰度扩展并确认旧版本无请求后撤销旧密钥。
4. 运行固定健康检查和一次受权问答；记录 Profile、密钥版本标识、时间和操作者，不记录密钥值。
5. 失败时恢复旧引用版本而不是从日志找明文密钥。

## 验收证据模板

每次任务记录：jobId、idempotencyKey、operationType、requester、reviewer、范围摘要、dry-run 计数、开始/完成时间、结果计数、失败码、审计 ID、回滚/补偿动作和审批单编号。
