# 14｜换场景时怎样选：方案矩阵与答辩方法

[返回目录](README.md)。这是前三个新增专题的复习页，不代替逐题长回答。

## 1. 先看错误类型，而不是先选框架

| 业务信号 | 优先考虑 | 不应直接跳到 | 需要付出的成本 |
| --- | --- | --- | --- |
| 原文表头/数字解析丢失 | Parser/OCR/审核 | Agent 多查几轮 | 样本、格式适配、重处理 |
| 片段脱离上下文 | 结构切分、父子块、上下文表示 | 无界扩大 topK | 表示构建、去重与预算 |
| 黑话/口语错配 | 术语词典、多查询；再试 HyDE | 替换全部模型 | 查询噪声、额外调用 |
| 全年合计、跨表统计 | 受控结构化查询 | 对 TopK 求和 | 类型、主键、单位、权限 |
| 全库主题概览 | 有覆盖记录的批处理、层次摘要 | 声称 TopK 已穷尽 | 全量处理与失效维护 |
| 稳定知识的学习导航 | LLM Wiki | 每次在线重新总结 | 编译、审核、依赖治理 |
| 根据证据决定下一步 | 受控 Agentic | 不设上限的自由 Agent | 路由、工具安全、恢复 |
| 当前订单/审批状态 | 授权业务 API | 用旧知识库导出表猜 | API 契约、实时性和审计 |
| 稳定实体关系多跳 | 关系表/图检索试点 | 为“图”而上图数据库 | 实体消歧、边来源、更新 |
| 相似问题重复出现 | 先向量/证据缓存，再评估答案缓存 | 仅靠语义距离复用答案 | 版本/权限/条件失效 |

## 2. 三套链路的职责分界

| 层 | 输入 | 输出 | 是否天然可信 | 失败时怎么办 |
| --- | --- | --- | --- | --- |
| 原始 RAG | 问题、身份、知识快照 | 原始候选、证据及引用 | 仍需适用性/引用校验 | 诊断最早失败层、有限补检索 |
| Wiki 编译 | 受控来源快照 | 候选主题页、来源依赖 | 否，是派生产物 | 审核/失效，原始 RAG 继续使用 |
| Agentic 决策 | 任务、已有证据、预算 | 下一步动作建议 | 否，必须由代码验证 | 停止、澄清、部分回答或有界降级 |
| 业务 API | 身份、资源参数 | 时点化业务事实 | 需要接口和归属验证 | 标记实时信息不可用，禁止猜测 |

你应能明确说出：“Wiki 不负责决定用户能否读资料，Agent 不负责批准自己越权，Milvus 不负责宣布业务发布，LLM 不负责证明全表已完整统计。”

## 3. 不同题型的口述结构

面试官问“怎么做”时，用六段回答：

1. **目标**：用户究竟要找事实、做统计、了解流程还是执行业务操作？
2. **约束**：权限、时效、硬件、延迟、离线环境和风险等级是什么？
3. **最小方案**：先用哪条路径，数据和控制权分别在哪里？
4. **失败处理**：超时、缺数据、冲突、撤权、重复执行分别怎么处理？
5. **验证**：用哪些正例/反例，指标粒度与分母是什么？
6. **升级条件**：什么时候现有方案不够，新增能力的收益怎样超过成本？

面试官问“你做过吗”时，不套上述设计充当经历。回答：“当前实现是……；这部分尚未上线，我的设计是……；会用……验证。”可以主动展示源码、验收记录与一个失败样本。

## 4. 三组连续追问练习（含答题要点）

### A. “我只要一个智能问答，你为什么搞 Wiki？”

先承认未必需要。若主要是精确条款查询，原 RAG 更直接；若大量重复的跨文档学习/流程导航，Wiki 可预编译。接着说明派生产物的权限、来源更新、审核与成本。最后给试点与退出条件，而不是说同行都做。

### B. “你让 Agent 自动选择工具，怎么证明不会失控？”

不是证明模型永不犯错，而是让犯错不能突破边界。工具白名单、服务器授权、Schema、只读、全局预算、取消、租约及最终门禁形成限制。再说可检验的反例：恶意文档、参数越权、循环、超时、崩溃恢复。没有这些测试，不能只靠 system prompt 宣称安全。

### C. “Wiki 更完整，Agent 更智能，为什么还保留传统 RAG？”

原始资料是事实证据来源，直接检索也是低成本快路径；Wiki 可能过时/遗漏，Agent 可能规划错误或超时。保留原链路既是职责分工，也是回退与公平评测基线，不是技术不先进。引用、权限和版本门禁统一，避免三套系统产生三种互相矛盾的事实。

## 5. 能力声明清单

当前项目可结合源码讲：解析/Block/Chunk、受控检索、RRF、专用与可选 LLM 精排、证据/引用、版本发布及运行底座。
内网由用户确认但本地待对齐：Dense + Milvus 内置 BM25 的具体 Adapter。
当前计划但未实现：单开关 Agentic Auto、LLM Wiki 编译与企业同步。
进一步的选型方案：HyDE、token 级多向量、完整多模态、CDC、语义答案缓存、双时间审计、通用 NL2SQL、多 Agent、长期记忆。

上述划分不意味着现有能力已在所有企业样本和规模上验收；“有实现”和“业务效果被证明”仍要分开。
