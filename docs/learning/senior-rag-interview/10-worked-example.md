# 10｜贯穿算例：一张差旅表如何变成有依据的答案

[返回目录](README.md)。以下文档、ID、分数和耗时预算均是教学合成数据，不是从内网导出的真实记录，也不是本轮运行结果。

## 1. 先看原始资料，不从向量开始

《差旅制度》v3 的“国内住宿”章节：

| 城市 | 职级 | 标准（元/晚） |
| --- | --- | --- |
| 北京 | P6 | 700 |
| 上海 | P6 | 800 |
| 上海 | P7 | 1000 |

表下注：展会期间超标准住宿，须提前经部门负责人批准。另有《出差审批规则》说明普通出差的审批流程。

用户问：“上海 P6 住宿上限多少？展会期间能不能超过？”这个问题至少需要表格和例外条款两个证据，不是只找到数字 800 就完成。

## 2. Block 和 Chunk 如何各司其职

解析层产生表格 Block B1（rows、表头、位置）及段落 Block B2（表下注）。Chunk 层将表格按行组生成 C1/C2，同时保留与原 Block、父章节的关系；例外条款生成 C3。真实 ID 由项目算法生成，这里用短名方便理解。

表格检索文本可能是：

```text
差旅制度 > 国内住宿
| 城市 | 职级 | 标准（元/晚） |
| 上海 | P6 | 800 |
```

如果只序列化为 `上海 P6 800`，单位和字段含义很弱；如果漏掉“展会期间”段落，任何后续模型都难以可靠回答例外。原始位置、结构化表格和用于 Embedding 的表示分别保存，不能只留最后一个字符串。

## 3. 向量相似度到底在比较什么

余弦相似度：`cos(q,d)=q·d / (||q|| ||d||)`。例如 q=(1,0)，d1=(0.8,0.6)，其相似度为 0.8；d2=(10,0) 相似度为 1。内积分别是 0.8 与 10，说明未归一化时向量模长会影响内积，不能把内积和 cosine 分数直接混用。

当双方都单位归一化时，内积等于 cosine；平方欧氏距离为 `2−2cos`，因此排序有对应关系。实际项目仍应使用与模型约定一致的归一化、距离和 Profile，不因这个数学关系随意更换配置。向量相似度是相关性线索，不知道“P6 和 P7 的额度不能互用”。

## 4. BM25 为什么可能把另一条资料排高

常见单词项贡献写作：

```text
IDF(t) × tf(t,d) × (k1+1)
------------------------------------------
tf(t,d) + k1 × (1-b+b×len(d)/avgdl)
```

再对查询词项求和。具体实现可能包含不同 IDF、查询侧处理与参数约束，应以部署版本为准。下面仅教学：N=1000，某词出现在10篇，使用 `ln(1+(N-df+0.5)/(df+0.5))` 得 IDF≈4.557；tf=3、k1=1.2、b=0.75、文档长度=200、平均长度=100，则该词贡献约 5.898。

词越稀有通常信息量越大，出现多次的收益逐渐饱和，长文有长度校正。分词没保住 P6、精确城市被遗漏或只索引了短摘要，都会影响结果；调 b/k1 不能恢复没有入索引的词。

Dense 和 BM25 原始分数尺度不同，所以进入 RRF 时取各自排名，而不是 `0.8+5.898`。公式层面的对照参见 [Milvus BM25 Function](https://milvus.io/docs/bm25-function.md)。

## 5. 从召回到答案，逐层看“丢失”在哪里

假设各路线同时召回 P6、P7、旧制度和展会条款。RRF 按排名形成候选池，PG 回源排除无权/不在有效 Manifest 的来源，Reranker 判断对当前完整问题的相关性。不要在精排前只剩一个数字块。

之后 Evidence 应至少有：

| 待回答事项 | 所需证据 | 如果缺失 |
| --- | --- | --- |
| 上海 P6 普通住宿上限 | 城市+职级+800+元/晚 | 不能用 P7 或北京替代 |
| 展会期间能否超过 | 例外范围+须提前批准+批准主体 | 只能给普通标准，说明例外依据不足 |

Context 放直接命中与必要表注；父章节只补新内容。生成答案可以是：“普通标准为800元/晚；展会期间可在提前获部门负责人批准的条件下超标准。”两项分别引用支持证据。仅有第一项时不应输出第二项，也不必把第一项完全拒绝。

## 6. 如果系统答成“1000”，你怎么排查

按最早错误层定位，而非一起修改参数：

- B1 已把 P6/P7 行错位：Parser 或表格结构问题。
- B1 正确，C1 丢了职级：切分/序列化问题。
- Chunk 正确但 P6 未召回：查询、分词、模型或 ANN 问题。
- 召回有 P6，精排只剩 P7：候选和精排适用性问题。
- 精排有 P6，Context 裁掉：预算/覆盖组织问题。
- Context 有 P6，答案仍写 P7 的数字：生成/支持性校验问题。
- 答案正文正确，引用打开别的文件：身份映射/版本绑定问题。

这个分类也解释为什么一味换更大的 LLM 或加 Agent 循环不一定解决错误。

## 7. 用四个样本检查是否真的修好了

1. 上海 P6，普通期间：800 元/晚。
2. 上海 P7，普通期间：1000 元/晚，不能被 P6 样本修复误伤。
3. 上海 P6，展会期间：例外必须带提前批准条件。
4. “上海住宿多少钱”未给职级：应说明与职级有关并澄清，不能默认 P6。

再加入无权用户、旧版本、发布后更新、OCR 把 800 识别成 300 的情况。分别测解析保真、检索覆盖、结论正确、引用支持和端到端耗时，不用一个总分覆盖所有层次。

## 8. 延迟与成本怎么回答

假设检索阶段两路分别耗时 80ms 和 120ms，真正并行且无排队时召回主阶段约由较慢的 120ms 决定，再加调度与融合开销，而不是直接加成 200ms。相反，如果日志看似两个节点并行但实际连接池串行，仍可能接近相加，需从 Trace 验证。

最终答案的总预算包括排队、改写、向量、检索、精排、生成和校验。自动规划允许额外模型调用也不等于必须调用满三次。报告每题实际次数、输入输出 Token 和阶段耗时；没有 usage 字段要标未知，而不是报 0 成本。
