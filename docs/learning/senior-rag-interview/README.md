## 面试前先记住这些真实边界

| 结论 | 可以怎么说 | 不可以怎么说 |
| --- | --- | --- |
| 当前传统 RAG | 受控 LangGraph、有限改写和重检索、证据校验 | 已上线完整自主 Agent |
| 内网检索 | 用户确认 Dense Embedding + Milvus 内置 BM25 | BGE 稀疏向量等于 BM25；本地已经核实 BM25 Adapter |
| BM25 代码差异 | 本地可见的是 SparseVector/IP 路线，内网 Adapter 待对齐 | 单改 env 就能把两种协议等价替换 |
| 表格 | 二维行列、合并信息、行组切分、重复表头 | 任意复杂表格可无损还原、能精确汇总所有行 |
| OCR | 兼容纯文本；缺少坐标/置信度保持未知 | 纯文本 OCR 能直接提供准确 bbox 和单元格关系 |
| Tokenizer | 使用 cl100k_base 做本地 BPE 预算 | 它与 GLM/BGE 的 tokenizer 完全一致 |
| 路由 | CHAT/KNOWLEDGE/CLARIFY/REJECT 规则路由 | 已有联网/CRM/ERP 自主工具选择 |
| 可观测性 | 有 runId、阶段事实、快照、引用链 | 只凭 traceId 就能完全复现模型输出 |
| 质量 | 存在测试和验收记录 | 合成测试通过即证明内网业务准确率很高 |

Agentic Auto 和 LLM Wiki 目前是计划，见需求目录；本手册明确把相关问答写为未来设计。

## 学习节奏与自测

第一轮理解 Q01–Q30，拿一份合成制度、一张合并表格、一份扫描件走入库。第二轮理解 Q31–Q50，对一道问题追踪候选和答案。第三轮用 Q51–Q66 定位一个人为制造的失败，再用 Q67–Q72 做场景口述。第四轮学习 Q73–Q108 的未实现方案，按“何时值得、如何落地、失败怎样恢复、怎样验证”训练架构设计能力。

每题自评 0–3：0 只认识名词；1 能讲原理；2 能对应项目代码和失败处理；3 能给出实验、指标和替代方案。资深面试最容易拉开差距的是第 2、3 层，而不是多说几个框架名字。

本轮只新增学习资料和图，不改变业务代码、配置或 diff 交付目录。
