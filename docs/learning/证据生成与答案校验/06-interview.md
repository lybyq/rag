# 证据生成与答案校验：面试追问

## 为什么需要 EvidenceBundle，不直接把 TopK 拼给 LLM？

TopK 没有覆盖、冲突、权威度和缺失条件语义。EvidenceBundle 把“是否足以回答”变成可测试的服务端
事实，LLM 只负责表达，不负责放行。

## 为什么扩展 Parent/Neighbor 后还要鉴权？

原始 Child 通过权限不代表任意关系目标都安全。关系可能跨版本、旧 revision 或错误数据；扩展是一次
新的资源读取，必须再次验证同文档版本和当前 ACL。

## Reranker 挂了为什么可以降级，LLM 挂了为什么通常不能返回草稿？

Reranker 只改变相关性次序，回退 RRF 不扩大权限，且降级会降低置信度。生成模型失败则没有合法
Draft，不能编造正文；系统应返回受控拒答或稳定失败。

## Semantic Judge 为什么不能覆盖规则？

撤权、时间、版本、金额和引用存在性是确定事实。让概率模型推翻它们会破坏安全边界。Judge 只补充
代码无法确定的语义蕴含，并保存模型 revision 和调用原因。

## 为什么最多重生成一次？

修复一次能覆盖常见 Schema/引用/表达问题；继续循环收益递减，却会放大费用、延迟和不确定性。
硬上限也是 LangGraph 可终止性和容量预算的一部分。

## 如何证明答案不会未经校验流出？

图中间节点只写脱敏 Step 和阶段事件；Controller 没有 Draft 流接口。只有 `finalizeAnswer` 后，
`completeRun` 才在单事务写助手消息、引用、报告、Run 终态和 Outbox。SSE 读取的是事务后的事件投影。

## citationId 为什么不是 chunkId？

Chunk ID 可能可猜、可跨 Run 复用，还会暴露内部数据模型。不透明 UUID 只在服务端关联真实资源；
预览每次重新鉴权，撤权后即使知道 UUID 也只能得到 404。
