# M06 概念：一次提问不是一条 HTTP 请求

## 1. Conversation、Message 和 Run 各解决什么

- Conversation 是用户长期可见的会话容器，只属于一个 `userId`。
- Message 是会话里的用户问题或助手答案事实。最终答案必须是独立消息，不能只藏在日志或事件里。
- RagRun 是“一次逻辑提问”的执行记录，保存幂等键、状态、Deadline、冻结配置和消息引用。
- RagRunStep 是 Graph 节点审计，不保存证据全文，只保存输入/输出摘要、计数、错误码、耗时和 Trace。
- ConversationState 是有限记忆：短窗口 ID、摘要、确认实体、最近引用。它不是完整聊天记录副本。

一条用户消息对应一个 Run；一个成功 Run 最多对应一条助手消息。这个约束让重试不会生成两份答案。

## 2. 传输状态和业务事实不能混为一谈

SSE 显示“正在检索”属于传输投影，Redis Stream 可以保存；答案正文和 Run 终态属于业务事实，必须先进入 PostgreSQL。Redis Key 过期后，用户仍能通过 `GET /runs/{runId}` 查到最终状态。

## 3. 幂等不是“查一下再插入”

两个并发请求都可能先查到“不存在”，再各自插入。M06 使用三层保护：

1. 规范化并限制 `Idempotency-Key`；
2. 以 `userId + key` 取得 PostgreSQL 事务级咨询锁，让同键并发排队；
3. `(owner_user_id, idempotency_key)` 唯一约束作为最后防线。

同键同请求返回原 Run；同键不同问题返回 409。幂等检查发生在创建用户消息之前，所以重放不会多出一条消息。

## 4. 乐观锁和状态机分别防什么

状态机防非法方向，例如 `CANCELLING → COMPLETED`；乐观锁防两个合法操作同时覆盖，例如超时扫描与 Worker 完成同时发生。两者必须同时存在。

终态 `COMPLETED/FAILED/CANCELLED/EXPIRED` 不可逆。用户发起取消先进入 `CANCELLING`，等执行器真的停止才进入 `CANCELLED`。

## 5. Outbox 为什么是关键

PostgreSQL 与 Redis 没有一个共同事务。如果事务内写答案、事务外直接发 Redis，进程可能在两步之间崩溃。Outbox 把“稍后要发的事件”与答案一起提交；独立 Publisher 可以无限重试，Redis Lua 又保证重复 sequence 不会产生第二条事件。

## 6. 为什么要冻结快照

一次长 Run 执行期间，管理员可能发布新 Manifest 或升级模型。若每个节点都读取“当前配置”，同一答案会混用不同索引和模型，无法复现。创建 Run 时冻结全部版本，既是可解释性证据，也是故障回放输入。

## 7. 有限记忆与重新鉴权

历史答案昨天可见，不代表今天仍可见。M06 为答案保存来源空间摘要，为会话摘要保存来源空间 ID。每次读取都重新缩小授权范围；撤权后隐藏相关正文和有限记忆，不能因为“曾经看过”就永久绕过 ACL。
