# 受控 Agentic RAG Auto 完整实施计划

- 日期：2026-09-24。
- 状态：待实施；本文所有需求尚未验收，不代表代码已经具备这些能力。
- 交付决定：直接交付完整 auto，由一个总开关控制；不先交付手动 traditional/agentic 产品模式。
- 顺序：现有 RAG → 受控 Agentic RAG Auto → 可选 LLM Wiki。Wiki 不是本阶段前置条件。
- 环境：单企业内网、userId + roles、GLM-4.7/vLLM、Dense Embedding、Milvus 内置 BM25、Reranker、纯文本 PaddleOCR。
- 本次只制定计划和决策，不改业务代码、不打包镜像、不修改已有 diff。

## 1. Executive Summary（目标与成功标准）

### 1.1 问题与方案

当前已经有改写、子问题、有限重检索和证据校验，不重新建设一套 RAG。新增受控决策层：
简单且证据完整的问题直接使用原有生成链；复杂或存在明确证据缺口的问题按需规划、调用只读工具、补证后回到统一答案校验。
模型只能提出动作，权限、预算、版本和是否可以执行由代码决定。

开关关闭：走原有链路。开关开启：自动判断快路径或增强路径，用户不需要选择模式。
完整交付包括路由、计划、工具、预算、恢复、前端事件、测试、教学文档和部署配置，不把 auto 留到后续阶段。

### 1.2 成功标准

1. 开关关闭时，原链路契约及回归测试全部通过，不发生任何 Agent 规划调用。
2. 标记为简单且证据充足的合成测试样本，额外 Agent 模型调用为 0；不得通过关键词命中便跳过证据检查。
3. 权限、来源、版本、终态和取消门禁测试全部通过；未经授权的内容、文档名称及统计数量泄漏为 0。
4. 所有执行都受 Run 总 Deadline、动作预算及 Provider 重试上限限制；重复动作不会形成无限循环。
5. 内网同题对比以复杂问题完整正确率提高至少 10 个百分点、简单题正确率下降不超过 2 个百分点、简单题 P95 增幅不超过 10% 为初始建议目标；不是已测结果。小样本同时报告原始题数和错误案例，业务验收前固定数据集和阈值，不为通过验收临时改阈值。

用户已确认：沿用现有 Run 总超时；复杂问题接受最多额外 3 次规划/缺口判断模型调用，优先保证完整性。简单问题不增加此类调用。复杂题绝对延迟依赖内网模型吞吐，不承诺每道复杂题必然比原链路快。

## 2. User Experience & Functionality（需求与体验）

### 2.1 用户故事

- 作为普通用户，我只想正常提问，由系统判断是否需要深入检索；简单题不为 Agent 额外等待。
- 作为业务用户，我希望跨文件问题分别核对各事项；缺失信息时说明缺什么，不把找到一部分说成全部回答。
- 作为管理员，我希望通过一个开关启停增强能力，保持已有模型、知识库和接口可用。
- 作为运维和开发者，我希望能从 runId 看出实际动作、停止原因和各阶段耗时，而不在日志里暴露敏感正文。

### 2.2 可验收需求

- [ ] `AGT-001` 总开关关闭走原图，开启直接启用 auto；旧请求不必增加字段，公开接口不增加强制模式参数。
- [ ] `AGT-002` 自动路由结合问题结构、现有路由及首轮证据覆盖；记录 FAST、ENHANCED、CLARIFY 等服务端决策码，不只依赖字数/问号数量。
- [ ] `AGT-003` 增强计划含待回答事项、依赖和缺失条件；最多 4 个事项，保留金额、日期、地区、职级等用户条件，禁止凭模型补造条件。
- [ ] `AGT-004` 按事项记录 SUPPORTED、MISSING、CONFLICT、NEEDS_USER_INPUT；引用必须指向真实已授权证据，模型自评分不作为事实成立的证明。
- [ ] `AGT-005` 受控工具支持混合搜索、指定文档内搜索、上下文扩展、适用版本元数据核对；不存在的文档 ID、越界空间或非法参数直接拒绝。
- [ ] `AGT-006` 补检索针对缺口，只扩展尚未覆盖的事项；指纹去重、无新增证据停止；一次无增益动作仍可尝试不同的合理工具，但必须受总预算约束。
- [ ] `AGT-007` 支持最终回答、部分回答、澄清、冲突说明、证据不足、超时和取消；不静默丢弃未回答事项。
- [ ] `AGT-008` 前端展示真实处理时间线、等待提示、取消与断线恢复；不展示私有思维链，不展示未经核实的计划完成状态。
- [ ] `AGT-009` 两条路径共用最终生成、引用复核、规则校验及既有可选语义校验；Agent 无权关闭安全门禁。
- [ ] `AGT-010` 新客户端兼容旧事件，新增事件需版本化；已有业务问答接口同样获得 auto 能力，无需独立 Agent API。

### 2.3 时间线

示例只按实际事件展示：

- 正在检索你选择的知识空间。
- 已找到可访问资料，正在核对问题涉及的条件。
- 已完成首轮检索，正在补充查询适用范围。
- 正在根据资料整理答案。
- 正在核验引用及适用条件。
- 本次等待较久，你可以取消。

文档数、证据数来自后端去重后的已授权结果；事件重放重新校验可见性，撤权后不继续展示旧文档名称或计数。未知总工作量不显示假百分比；等待时长不是伪造处理进度。

### 2.4 非目标

不实现自由上网、任意 SQL/脚本执行、写业务系统、多 Agent 协作、图数据库、Wiki 编译、长期自主记忆。
不以本阶段重构上传/Parser/OCR/索引发布为目标；若发现独立故障，单独记录需求，不让 Agent 掩盖底层错误。

## 3. AI System Requirements（模型、工具与评测）

### 3.1 自动执行策略

1. 在现有 Run 身份和 Manifest 快照下做轻量规则路由；非知识问答沿用既有处理。
2. 明确的多事项/比较/依赖问题可直接进入结构化规划，再调用检索；其他问题先进行一次现有检索和证据检查。
3. 简单且证据完整，直接生成；存在缺口或跨资料依赖，进入增强路径，复用已有候选，禁止无条件重跑首轮。
4. 增强路径维护事项覆盖表，选择白名单动作，执行后更新证据及缺口。
5. 已完成、需要用户补条件、存在无法消解冲突、无增益或预算不足时停止，进入统一答案后半段。

这两条入口共享同一套决策状态，不把两条路径分别复制成两套完整问答实现。复杂性路由错误必须纳入评测，auto 不承诺永远分类正确。

### 3.2 工具契约（拟新增）

| 工具 | 可接受参数 | 结果与约束 |
| --- | --- | --- |
| search_knowledge | query、服务器验证的范围提示、受限 topK | Dense + BM25 候选经 PG 回源；权限过滤由服务端生成 |
| search_document | 已知 documentId、query | 必须属于当前允许空间和有效 Manifest，不能遍历无权文档 |
| expand_context | 已授权 chunkId、受限窗口 | 父章节/相邻块/表头，受 token 和版本约束 |
| inspect_applicability | 已授权 documentId、证据关联的条件 | 返回现有版本、生效范围等元数据；不凭空推导“最新即适用” |

ANSWER、CLARIFY、STOP 是受校验决策，不是可绕过最终生成的工具。工具返回结构化 observation 与证据 ID；文档内容属于不可信数据，不能变成系统指令。

- [ ] `AGT-011` 通过独立 AgentDecisionPort 和现有 Model Gateway 调用 GLM；Zod 严格校验动作枚举、字段、长度和引用。
- [ ] `AGT-012` 验证 GLM 的结构化输出能力；不强制依赖原生 tool_calls。允许受控 JSON 输出适配，但不执行自由文本命令；格式修复也计入模型预算。
- [ ] `AGT-013` 决策上下文只包含当前用户可访问的必要证据；Prompt 注入、伪造工具调用和越权参数必须有测试。
- [ ] `AGT-014` 计划、工具、HTTP 重试与旧图补检索共用预算，不能出现“Agent 3 轮 × 原检索 2 轮 × 答案补检索”放大。
- [ ] `AGT-015` 每个远程调用支持 Deadline、单次超时、AbortSignal、错误分类和 Trace；Provider 重试遵守剩余时间和重试总额。

### 3.3 Dense + Milvus 内置 BM25 的边界

用户已确认内网混合检索由 Dense Embedding 和 Milvus 内置 BM25 组成。BM25 路线不要求 Embedding 提供 /pooling 或 sparse 向量；Agent 只消费统一检索结果。

但本地审阅事实是：milvus-vector-index.adapter.ts 当前可见 searchManifestSparse 接受 SparseVector，Collection 创建路径配置 SparseFloatVector，未看到明确的 BM25 Function 与原文查询接口。内网已调通实现与本地需要做差异核对；不能把这两个路线当作同一个协议。

- [ ] `AGT-016` 开始实现前对齐内网 BM25 Adapter、Collection/Profile 和查询契约；补充“Dense 来源”和“词法检索来源”能力声明，不用 Embedding sparseFormatVersion 代表 BM25 能力。
- [ ] `AGT-017` 能力探针及契约测试覆盖 Dense + BM25、Dense-only 降级、旧模型 Sparse Profile；BM25 故障降级需符合现有策略并可观测，不能静默假装双路成功。

优先复用内网已验证 Adapter，不覆盖现有 Collection，不自动改 analyzer、字段或索引，也不把重建语料作为默认前置。若本地确实缺少该 Adapter，应先取得内网脱敏代码/契约再合并；如确需索引迁移，另行确认迁移范围与回滚计划。

### 3.4 评测与强制测试

- [ ] `AGT-018` 原有测试保持；领域规则先写失败测试，JSDoc/测试关联 AGT 编号。
- [ ] `AGT-019` 每个新增外部 Port 覆盖正常、超时、取消、Schema 错误、429/5xx、版本不匹配和部分失败。
- [ ] `AGT-020` 对同一套冻结数据集运行开关开/关对比，统计正确性、事项覆盖、引用支持、误拒答、延迟、模型次数及费用/Token（服务不返回 usage 时标为未知，不填 0）。
- [ ] `AGT-021` 强制覆盖简单题、多事项、跨文档依赖、模糊条件、冲突/旧版本、无答案、Prompt 注入、撤权、Dense/BM25 单路故障和超时取消。

本地提供不少于 40 道公开/合成样本及可重复运行报告；另提供内网业务数据集模板和命令。Mock 通过仅证明编排，不代替 GLM 和实际语料质量验收。内网业务评测由用户在内网执行，未执行时明确标注未完成。

### 4.3 配置草案（待实现，不是现有变量）

实施时所有 env 示例附以下同等粒度的中文注释，真实密钥不写入示例：

```dotenv
# 总开关：true 自动选择快路径/增强路径；false 完整使用旧链路。
# 代码中缺省为 false 保护旧部署；明确启用的新部署模板写 true。
AGENTIC_RAG_ENABLED=true

# 一次问题最多拆成几个待回答事项，避免一个问题变成大型研究任务。
AGENTIC_MAX_SUBQUESTIONS=4

# 最多额外调用几次规划/缺口判断模型；格式修复也占次数，不包含最终答案生成。
AGENTIC_MAX_DECISION_CALLS=3

# 最多多少次工具动作；首次检索也计入，不能每进入一个子图就重新计数。
AGENTIC_MAX_TOOL_CALLS=6

# 工具动作向各空间/检索路线展开后，最多允许的检索逻辑请求数。
# Dense、BM25 各算一次；实现前与当前允许空间数量校准，防止大范围请求无声截断。
AGENTIC_MAX_RETRIEVAL_REQUESTS=24

# 同时最多执行几个互不依赖的工具动作，避免挤满内网模型和数据库。
AGENTIC_TOOL_CONCURRENCY=2

# 单次决策模型最多等多久；实际值还要受 Run 剩余时间限制。
AGENTIC_DECISION_TIMEOUT_MS=8000

# 整个增强决策和工具阶段的耗时上限，不会延长现有 Run 总超时。
AGENTIC_MAX_DURATION_MS=20000

# 至少给最终生成和校验预留的时间；不足时停止补查，安全部分回答或澄清。
AGENTIC_ANSWER_RESERVE_MS=15000

# 连续多少个动作没有新增有效证据就停止；重复动作直接跳过且记审计。
AGENTIC_MAX_NO_GAIN_ACTIONS=2
```

这些是初始保护值，不是 GLM 性能结论。启动校验正整数、范围和总超时关系；预算必须覆盖最终生成保留时间，否则拒绝不合理配置。每动作响应大小、决策输入 token 上限和 Provider HTTP 重试额复用/补齐现有配置，不允许无界上下文。

- [ ] `AGT-027` 单开关及预算配置有 Schema、中文注释、默认值、错误提示和配置测试；不引入强制的 AGENTIC_MODE 三模式选择。
- [ ] `AGT-028` 原 ANSWER_LLM_EVIDENCE_RERANK_ENABLED、ANSWER_SEMANTIC_JUDGE_ENABLED 继续独立生效，auto 不偷偷开启它们；基础引用/权限/规则校验不可关闭。

### 4.4 失败语义与可观测性

规划协议失败：剩余时间允许时使用已检索证据与旧规则；没有执行首轮时可受预算约束地执行一次原检索。不得整体重启一遍完整流程。
工具部分失败：保留有效证据，记录降级，只回答能够支持的部分。证据仍不足时明确拒答/澄清。
总 Deadline 耗尽：沿用超时终态，不在超时后继续生成“兜底答案”。

- [ ] `AGT-029` Trace 记录决策码、工具类型、预算余额、耗时、退出原因、降级原因和模型身份；指标标签不使用问题、documentId 等敏感或高基数值。
- [ ] `AGT-030` 沿用 SSE 可靠投递和恢复，阶段文案来自后端事实；前端覆盖 loading、空、失败、重试、无权限、取消与超时。

## 5. Risks & Roadmap（实施批次与门禁）

### 5.1 风险

| 风险 | 对策 |
| --- | --- |
| Agent 增加延迟 | 简单题 0 额外规划；复杂题预算、去重、生成时间预留 |
| 错误地把问题判为简单 | 首轮证据覆盖检查可升级路径；多事项漏答纳入回归 |
| 生成缺口本身判断错误 | 事项/引用结构校验、有限补查、最终原文证据门禁 |
| 内网 BM25 与本地接口不同 | 实施前对齐 Adapter/契约，禁止自动覆盖 Collection |
| 模型 429/拥塞 | 有界并发、重试预算、复用现有模型调用容量约束 |
| 旧图多层重试放大 | 一个共享账本；增强路径内的旧重试服从同一预算 |
| 进程崩溃/取消后仍运行 | 租约隔离、预留预算、AbortSignal、过期结果拒收 |
