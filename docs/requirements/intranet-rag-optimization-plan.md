# 内网 RAG 正确性、性能、模型适配与业务接入优化计划

> 日期：2026-09-12，2026-09-13 完成代码收口。状态：本轮约定的代码、迁移、接口、前端和源码增量已交付并完成外网合成回归；未勾选项仅为必须依赖内网真实 Provider/性能样本、运行中的 PostgreSQL 集成环境的验收门禁，或明确列为后续 Sparse 升级的工作。用户明确要求本轮不重新打镜像，因此镜像项保持未勾选。

## 1. 本轮要交付的结果

1. 分清“没有召回”“召回后被剔除”“未进入模型上下文”“生成错误”“校验拒绝”，能用一次 runId 查明原因。
2. 修复已复现的来源、证据、置信度和拒答问题，不靠统一降低阈值让所有问题都回答。
3. 当前正式支持 Dense-only；后续运维提供 Sparse 时可验证、补建、灰度切换并回滚。
4. 对接内网 Embedding、BGE Reranker、GLM-4.7/vLLM 和纯文本 OCR，保留当前已调通的标准协议路径。
5. 让用户看见真实处理说明、耗时和可取消状态；数量和名称均来自权限校验后的事实。
6. 文档从上传到发布的每个阶段在主要页面可见；外部业务可通过有权限的 API 导入和维护知识库。
7. 交付配置说明、回归证据、源码增量目录和需要时重新构建的离线镜像。

计划与 env 注释已经交付，现进入代码实施。运行环境继续只使用一个企业身份体系 userId + roles，不增加多租户；不连接或修改内网生产数据。

- [x] 固定当前代码、配置 Profile、模型 revision、Manifest、请求样本和冷/热缓存条件（外网合成基线明确不冒充内网冷热缓存数据）。
- [x] 记录排队、规划、向量化、搜索、PG 回源、重排、证据扩展、上下文构造、生成、校验、发布各阶段耗时。
- [x] 记录一次 Run 的逻辑模型调用次数、修复次数、超时/取消类别及拒答原因；不记录 Prompt/正文到普通日志。
- [x] 建至少 40 个合成或批准脱敏案例：单文档直答、多文档综合、同义问法、编号/版本、表格、扫描件、无答案、过期/撤权、相似标题、真假冲突。
- [x] 检索诊断分别展示授权后候选数、去重文档数、重排保留数、证据数、上下文实际包含数，以及移除原因。

验收：相同版本条件下能重放失败样本；至少把问题归到一层，不能用统一“证据不足”覆盖所有错误。

## 5. 正确性修复（OPT-002～004）

### 来源与引用闭环（OPT-002）

- [x] 检查 chunkId → documentVersionId → documentId → spaceId → Manifest 链路与 Milvus 主键、PG 回源是否一致。
- [x] 检查父/相邻/表头扩展是否保持版本与内容 revision，引用预览的 ID/标题/位置是否一致。
- [x] 验证前端没有按结果数组下标、相似标题或旧消息缓存配引用。
- [ ] **内网 PG/权限验收**：永久测试覆盖同名文档、不同空间、同文本不同版本、重发布、相邻扩展、乱序返回和中途撤权。

验收：每个引用可回到对应授权文档与版本；无法复现的演示问题保留“待内网验证”，不勾成已修复。

### 覆盖、冲突和上下文（OPT-003）

- [x] 单问题不再仅凭存在候选就认定全部来源支持；保存相关性和覆盖判断依据。
- [x] 显式区分 raw logits 与已归一化分数，归一化只做一次；候选排名和置信度分开使用。
- [x] 只有相同业务主体、字段、适用范围等可比较事实才作为确定冲突；不能仅因不同数字或空标题判冲突。
- [x] Token 预算与单文档配额以问题覆盖为约束，记录被省略来源；避免父/相邻块挤掉真正回答所需的 SELF 证据。
- [x] 生成和校验使用实际送入模型的证据及可见片段，避免完整 Bundle 有依据但模型未见，或校验引用了被截去内容。
- [x] 核对 summary、claims 与最终正文一致，不能只校验 Claim 却放过 summary 中无依据结论。

验收：相关同义问题可回答，无关问题不靠高分强行通过；真假冲突、长文单来源和被裁剪关键段落都有失败测试先行。

### 重检索与拒答原因（OPT-004）

- [x] 核对 REWRITE_AND_RETRY 是否真正触发受限重检索，不能声明重试却直接走终止回答。
- [x] 在现有最多两轮与总 Deadline 内执行，不重复已完成的高成本步骤。
- [x] 用户可区分资料未覆盖、适用条件缺失、来源冲突、系统异常；内部诊断保留具体错误码，不泄漏无权文档是否存在。

## 6. 开关、回答策略与耗时（OPT-005～006）

### 可安全关闭 Judge（OPT-005）

- [x] 保留 BGE 专用重排，允许单独关闭额外 LLM Evidence Rerank。
- [x] Judge 开启：规则校验先行，确实需要语义判断的 Claim 才调用 Judge。
- [x] Judge 关闭：采用可核验的原文摘录/结构化事实策略，检查文字与来源对应；需要推断才能回答时明确部分回答或限制说明。
- [x] 禁止把 SEMANTIC 改个标签冒充已核验，禁止以“开关关了”跳过引用、权限、版本和数值门禁。
- [x] 修复关闭后重复触发 SEMANTIC_JUDGE_REQUIRED 的循环；四种双开关组合都有回归及模型调用次数断言。
- [ ] **后续运维增强**：管理端显示 env 默认、DB 系统/空间覆盖、当前生效值和新 Run 快照；已开始 Run 按快照执行。本轮已保证开关组合安全及 Run 侧行为，未扩展设置页。

验收：关闭 Judge 的摘录型用例不调用 Judge、不为缺 Judge 重生成；复杂推断不伪装成已通过语义校验。独立关闭 LLM 重排不关闭 BGE。

### 减少等待（OPT-006）

- [x] 根据基线减少可选串行模型调用、重复改写和无效上下文占用；真实 P50/P95 仍需内网补证。
- [ ] **内网真实慢调用验收**：验证 Deadline、重试、取消贯穿生成、Judge 和检索；取消后停止可停止的远程调用，晚到结果不发布。
- [ ] **内网 GLM/vLLM 验收**：GLM 请求策略按真实 vLLM 版本验证，可配置输出预算、结构化格式和已支持的推理参数；不得猜测参数即可生效。
- [x] 记录响应格式错误、截断、模型版本不匹配；推理文本不能混入答案 JSON，也不能用作引用事实。

性能验收：固定相同模型/GPU/并发/样本与冷热点条件，对比 P50/P95、首条真实状态时间、模型调用数、取消耗时和质量。优化目标为可选调用路径的 P95 降低至少 20%，这是内网实测目标而非承诺；没有基线不报虚构提升。

## 7. 内网模型适配（OPT-007～010）

### Dense-only 与后续 Sparse（OPT-007）

- [x] 正式内网 Profile 明确允许经验证的 dense 模式；Auth、模型身份、维度等其他校验仍执行。
- [x] dense 模式不请求不存在的稀疏接口；metadata、建索引、查询、缓存、发布快照和界面统一显示实际能力。
- [ ] **Sparse 服务恢复后实施**：Sparse 尚不可用与运行时 Sparse 故障采用不同状态，日志/指标可区分。
- [x] 避免把空/伪造 sparse 作为混合索引成功写入；不将缺少特定 URL 直接判成模型能力结论。
- [ ] **Sparse 服务恢复后实施**：探测真实 Sparse 契约 → 新 Embedding/检索 Profile → 为历史内容生成候选索引 → 数量/身份对账 → 业务评测 → 原子发布。
- [ ] **Sparse 服务恢复后实施**：升级期间旧 Dense Manifest 服务旧请求；Query 绑定相匹配 Profile；回滚只切 Head，不删除旧内容。

验收：没有 Sparse 的真实部署能入库并问答；恢复后不会只开查询权重而留下无稀疏数据的旧索引。

### Embedding/BGE（OPT-008）

- [x] 按协议返回映射批次 itemId、重排 candidateId/rank、分数类型、模型身份；缺失、重复、越界、乱序一律有契约测试。
- [ ] **内网 Provider 验收**：声明的 metadata 与探测到的维度/能力一致；无法从服务读取的版本标明配置来源，不冒充服务实测。
- [x] 标准协议 Adapter 保留，原生 Provider 差异在新增/扩展 Adapter 内处理，Domain 不读供应商参数。

### GLM-4.7/vLLM（OPT-009）

- [ ] **内网 GLM/vLLM 验收**：验证 served model name、chat/completions、结构化输出支持、finish_reason 与 content/reasoning 字段实际形态。
- [x] 生成、重排、Judge 使用相应任务输入；支持不同的合理输出预算，避免每一步按长回答规格执行。
- [x] 429/5xx、超时、取消、输出截断、错误 Schema 各自稳定分类；不能把所有故障转成业务证据不足。

### 纯文本 PaddleOCR（OPT-010）

- [x] 配置明确选择标准结构化或纯文本模式；响应 text/plain、JSON 字符串、JSON 文本字段按明确配置处理，不做无界猜测。
- [ ] **内网 OCR 验收**：请求方式根据真实样例确定：文件、Base64 或 URL。暂未知时只做接口边界和合成测试，不声称已连通。
- [x] 每次调用关联单个实际可识别目标；已知页/图片位置来自请求及解析事实，bbox/置信度未知保持未知。
- [x] 单个多页文件只返回整段文本且无法拆页时明确拒绝多目标映射；不复制到每页、不编造坐标。
- [x] 未知置信度的质量状态单独处理：保留文本及告警，不能简单设 0 或 1 冒充实测分数。
- [x] 空白结果、HTML 错误页、取消和超长响应沿用有界 HTTP 门禁；纯文本/结构化响应和未知置信度已有契约测试。

真实 OCR 上线门禁：拿到请求样例并用至少一张图片、一份扫描 PDF、一份混合 PDF 验证目标关联和质量路径。没有请求样例时这一门禁保持未勾选。

## 8. 真实处理说明时间线（OPT-011）

时间线展示系统可观察的执行事实，不伪造模型内部思考文字。正常用户看到简明说明；管理员另看诊断详情。

| 时点       | 用户文案示例                                       | 可信数据来源                                           |
| ---------- | -------------------------------------------------- | ------------------------------------------------------ |
| 授权完成   | 正在检索你选择的“财务制度”知识空间                 | 服务端确认可读的本次选择空间；未授权名称不展示         |
| 回源复核后 | 已找到 3 份可访问的相关资料，正在筛选              | 本次阶段授权后候选按 documentId 去重；数量未知就不报数 |
| 上下文完成 | 已保留 5 条证据，正在根据资料整理答案              | 实际 includedSourceIds 数量；不能使用向量原始命中数    |
| 校验开始   | 正在核验引用及适用条件                             | 真实校验节点开始事件                                   |
| 运行较久   | 本次等待较久，你可以取消                           | startedAt、终态及配置阈值；计时只表示等待，不增加进度  |
| 结束       | 回答完成／部分回答／需要补充条件／已取消／运行失败 | 持久化终态，晚到事件不得覆盖终态                       |

- [x] 扩展现有 Run 事件，包含单调序号、阶段/尝试、服务端时间、状态和可选授权计数；旧客户端兼容。
- [x] 通过现有持久化/SSE 投递；重连按序号重放、去重，轮询回退使用相同事实。
- [x] 计数只基于阶段当时已授权集合；前端再与当前可见空间求交集，无法确认名称时安全降级。
- [x] 心跳与业务进度区分；无新结果只更新耗时和连接状态，不制造“又筛选了几条”。
- [x] 取消按钮实时可用；断流和后台仍运行可区分。

验收：多空间部分无权、零候选、乱序/重复事件、重试第二次、断线重连、慢模型、取消与晚到结果均有回归；系统从未返回不可见文档的名称或数量。

## 9. 上传入库可视化（OPT-012）

- [x] 复用已有上传进度、Job events 和详情面板，上传完成后按服务端 jobId 直接打开阶段条。
- [x] 阶段覆盖上传、安全检查、解析、OCR、标准化、切分、质量审核、向量化、索引写入、对账、发布。
- [x] 不需要 OCR 显示跳过；等待人工审核显示等待；未知总量显示处理中，不能渲染为已完成 100%。
- [x] 各阶段显示真实耗时、处理单位（可用时）、失败原因及允许的重试/取消操作。
- [ ] **后续体验增强**：上传结束但未发布不能标为可检索；重处理新版本时同时标明旧版本仍在线。当前任务链只在 PUBLISH 成功后进入 SUCCEEDED，版本历史会保留旧版状态，但尚未增加独立“旧版仍在线”提示。

验收：从一次真实上传到发布，列表与详情状态一致；失败重试不伪造整体进度、不产生重复发布。

## 10. 外部业务 API（OPT-013）

第一批交付聚焦“外部业务向指定空间导入、更新、查询资料并发起问答”，复用现有 API 和 Outbox/BullMQ。

- [x] 给现有创建空间、批量上传、完成上传、查询任务、问答和引用 API 补一条可运行的调用示例，核对真实路由和鉴权。
- [x] 增加批次入口和批次查询：返回 batchId、逐文件状态和 jobId；大文件仍走已有直传，不把全部文件塞进一个 HTTP Body。
- [x] 支持 externalSourceId + externalDocumentId 对应文档，以及请求幂等键/内容 Hash；同内容重试不重复创建或发布，不同请求同幂等键报冲突。
- [x] 外部更新生成新版本，保留旧版直到新版发布；单文件失败不回滚已成功文件，可仅重试失败项。
- [x] 服务调用映射到受信任 userId + roles 并受空间 ACL 控制；不能默认管理员、不能由随意 Header 自报角色。
